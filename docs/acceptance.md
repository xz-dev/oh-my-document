# 验收场景草案

> **当前覆盖说明：** 本文件保留早期 S 编号和设计预期，未更新为当前可执行命令。复合来源示例已被 `separate-range-identity-and-location` 取代；当前执行证据见 [spec-traceability.md](../spec-traceability.md)。不得把本草案中的旧拼写当作 CLI 使用说明。

**历史草案，不能单独作为通过证明。** 部分行为现已实现并测试，但本文件本身不是产品测试报告。场景编号用于追溯 [需求基线](requirements.md)；当前契约以适用 OpenSpec delta 和实际可失败断言为准。

## 基础与管理边界

### S-01 无 Git 的完整路径（R-01、R-04）

Given 普通项目目录没有 `.git`，系统没有可用 Git 可执行程序；When import、建立范围关联、修改受管内容并检查；Then 核心跟踪仍可完成，不因缺少 Git 而无法计算变化或取得必要基线。

### S-02 非指定编码工具（R-01、R-03、R-19）

Given 文档与代码由任意编辑器或 agent 修改；When 通过同一 CLI 校验和更新；Then 不要求特定 agent/OpenSpec/Mermaid，不提供 AI 专属绕过。

### S-03 未 import 不纳管（R-06）

Given 发现项目配置但用户尚未 import 某目录；When 检查；Then 不因发现配置而自动纳管该目录。import 后新增文件另按 Q-04 定义，不能由此测试偷定。

### S-04 显式 import 元数据目录（R-06）

Given 用户明确选择 `.omd/`；When import；Then 不因目录名而拒绝或暗中排除。可能产生自引用脏状态，不要求工具掩盖或自动确认自身变化。

### S-05 follow 符号链接（R-07）

Given 已 import 范围内存在符号链接；When 读取跟踪内容；Then 使用目标文件内容，目标变化可被观察。断链、循环与重复路径的精确诊断待实现规格，但不得无限遍历或简单拒绝全部链接。

## 来源、坐标与关系

### S-06 初次标记及理由（R-08、R-09）

Given 某受管范围没有标记；When 查询覆盖；Then 为空且不计覆盖。When 建立并确认标记/关系；Then 保存理由及有效的版本依据，未过期时为已确认。

### S-07 脏不是空也不是已确认（R-08、R-09）

Given 已确认标记的所选内容被实际替换，原标记需更新；When 检查；Then 为脏，不算覆盖；保留原记录以供处理。不得只因曾有标记就仍算覆盖。纯位置位移的情形另见 Q-01。

### S-08 双向与逐层关联（R-02、R-10、R-11）

Given 总览图范围、细化图范围、设计段落及函数范围，以及另一语言实现；When 建立关系并从任一端查询；Then 能看到保存的关联及类型，不要求把整个内容压成文件级链接。跨未知元数据目录的全局查询不在本场景承诺内。

### S-09 文本 Unicode 坐标（R-12）

Given 包含中文、ASCII、补充平面字符和组合字符的文本；When 按选定编码解释范围；Then 使用解码后的 Unicode 字符序号，不混用 UTF-8 字节数或屏幕显示宽度。测试先根据 Q-07 固定索引起点/端点，不在场景里虚构数值。

### S-10 其他编码（R-12）

Given 用户在项目/全局配置或显式来源设置中指定其他编码；When 读取文本；Then 按配置解码后定位字符，而非始终假定 UTF-8。覆盖优先级和非法序列策略应先完成 Q-07。

### S-11 显式字节模式（R-13）

Given 文件含无法按文本解码的任意字节；When 使用 `proj:A:byte::file_path`；Then 按原始字节定位与跟踪，不要求文本解码，也不尝试解析内部格式。

### S-12 alias 语法（R-11）

Given 当前元数据目录定义了 A，且相应本地内容已按确定的解析规则准备好；When 使用 `proj:A:file_path` 和 `proj:root:file_path`；Then 分别指向 A 与当前项目。测试不把 `git:github.com/someprojectpath` 示例当作可联网的真实测试依赖。

## command

### S-13 JSON argv 边界（R-14）

Given 固定 executable 与包含空参数、空格、引号、反斜线、`::` 的 JSON 字符串数组；When 启动测试程序；Then 参数值、顺序和边界保持一致，不追加 OMD 动态展开。建议为测试编写专用 argv 回显进程，避免靠复杂 shell 输出猜测。

### S-14 合法成功输出（R-15）

Given 命令正常退出且 exit 0，stdout 为确定字节内容；When 采集；Then 该 stdout 可以成为本次内容观察，后续进入跟踪检查，不自动确认标记。

### S-15 stderr 与空 stdout（R-15）

分别验证 exit 0 + 非空 stderr，及 exit 0 + 空 stdout。Then stderr 不并入内容、不单独使该执行失败；空 stdout 是合法空内容。

### S-16 非零退出已有部分 stdout（R-15）

Given 命令先产生 stdout 后非零退出；When 采集；Then 本次失败，不以部分输出更新成功基线，不把旧快照当作本次成功。已有理由和基线不被失败覆盖。

### S-17 启动失败或异常终止（R-15）

Given executable 不存在或进程异常终止；Then 明确失败，而不是转成“成功的空内容”。超时、限额与进程清理按 Q-05 的工程规格测试。

## 规则与状态

### S-18 图约束检查（R-10、R-16）

Given 用例要求 spec 上连 UML、下连代码，另一个用例要求语言实现目录互相关联；When 缺少指定关系；Then 对应检查按配置提醒或失败，不用无关 link 充数。具体规则 schema 和数量语义由 Q-06 固定。

### S-19 规则可先于实现（R-16）

Given 用户已经制定规则但尚未补齐所有代码/文档；When 以提醒策略检查；Then 能报告缺口，不强制所有规则声明时就完成实现。指定失败策略时则如实失败。

### S-20 显式跳过/关闭（R-09、R-17）

Given 有空或脏标记导致某检查不满足；When 用户显式用参数跳过，或手动关闭对应检查用例；Then 该检查按显式选择处理，标记仍保持空或脏，不成为已确认。不得自动推断长期豁免。

### S-21 大规模格式变化（R-04、R-05）

Given 原始内容因格式化发生变化；When hash/diff 检查；Then 不以“可能只是格式”保证自动通过。工具可以产生待处理的脏标记，不声称已经证明行为无变化；精确范围判定按 Q-01 测试。

## 写入与存储

### S-22 旧 hash 冲突（R-18）

Given 操作依据版本 H，随后被管理记录或相关内容已改变；When 以 H 提交更新且不符合已定义前置条件；Then 报冲突，不覆盖，不自动改用新 hash 重试。H 的校验范围需先明确 Q-09。

### S-23 单写者（R-18）

Given 一个写入操作正在持有该存储的更新资格；When 第二个更新试图并发进入；Then 不允许二者同时修改权威状态。等待还是立即拒绝由工程规格确定，但不得退化为并发覆盖。

### S-24 缓存删除可恢复（R-20）

Given 权威记录及必要持久基线完整；When 删除 SQLite 后重新构建；Then 可恢复关联、理由、确认依据与相应查询，不丢唯一数据，不依赖 Git 恢复。重建不代表可以执行配置中的任意 command。

### S-25 路径覆盖优先（R-21、R-22）

Given 有效非空 OMD_CONFIG_PATH/OMD_CACHE_PATH 与 XDG 同时设置；When 解析目录；Then OMD 专用覆盖优先。没有专用覆盖时验证平台后备。环境变量异常值另由 Q-10 定义。

### S-26 外置目录与单层发现（R-21、R-23）

Given 权威元数据不使用默认 `.omd/` 名称或位于显式外置目录；When 按已确定的发现/映射规则加载；Then 可找到正确记录。单层发现不递归整个项目；多候选/失效路径按 Q-10 处理。

### S-27 可选 hook（R-04）

Given 项目使用 Git；When 用户主动安装 hook 并触发检查；Then 可提醒/阻止遗漏更新。不安装 hook 时核心仍正常。现有 hook 共存与暂存区范围按 Q-11 另测。

## programming-thinking skill 契约

下列包括 skill 行为评审、Lean 验证与 OMD 结构检查，不要求 OMD 核心自动理解命题的业务含义。它们均未执行；具体自动化方式待实现规格确定。

### S-28 顺序状态机的证明与闭环（R-24～R-28）

Given UML 源码有明确的顺序状态、守卫、输入域和错误分支；When 使用 skill 建模并证明所声明性质，再逐项翻译为实际代码、运行对应测试并建立两组直接范围 link；Then 分别报告模型证明、实现对应审查、实现测试及关联检查的实际结果，只声称这些证据覆盖的性质，不声称 OMD 自动完成跨语言语义证明。

### S-29 缺少细节或只有转写（R-24、R-25）

Given 只有高层说明/图像，或 Lean 只有流程枚举、成功输出而没有对应命题；When 请求程序性证明；Then 先要求补齐 UML 源码细节和证明义务，不把类型检查或文档转写报告为程序性证明。

### S-30 并发与多线程排除（R-24、R-28）

Given 正确性依赖线程交错、锁、调度或共享状态；When 请求此 skill 分析；Then 说明本工作流不适用，停止并发部分，不把它串行化后宣称并发已证明。若只处理隔离的纯顺序子过程，结论明确不覆盖调用方并发行为；不得据此声称已验证 OMD 的锁实现。

### S-31 必要直接 link 缺失（R-27）

分别给出 Lean 只有 UML link、只有实现 link、只有间接路径，以及链接的是图片/伪代码/未来路径/无关整文件的情形。When 检查证明闭环；Then 报告相应缺口，按配置提醒或失败，不用“存在某条 link”抵消必要直接范围关联。

### S-32 预构建先于实际实现（R-26～R-28）

Given UML↔Lean 对应完整、模型证明实际通过，但尚无实际实现；When 交付阶段结果；Then 可以如实报告模型证明完成，同时保留实现与其 link 的待办缺口，不创建虚假已确认目标，不称为完整交付，也不新增标记生命周期。

### S-33 一一对应翻译不能偷改逻辑（R-26、R-27）

Given Lean 已证明的转移和分支；When 实现额外增加、遗漏或重排影响行为的步骤，或目标类型引入未建模溢出/异常；Then 对应审查不通过，先修订 UML/Lean 并重新验证再翻译，不因 link 存在或示例测试成功就沿用旧证明。此语义审查由使用者/skill 完成，不声称核心自动发现所有差异。

### S-34 相关变更使旧证据不足（R-25、R-27、R-28）

Given 已有完整关联和验证记录；When UML、Lean、实际实现或其证明依赖发生相关变化，包括只改定理调用的转移定义；Then 重新核对受影响性质和两侧对应，记录依据与理由，不能复用旧文件/依赖版本的成功结果。范围迁移与脏传播的精确判定按 Q-01/Q-02/Q-09 确定，不在场景中暗定。

### S-35 空洞或假设掉结论的证明（R-25）

Given Lean 定理能检查通过，但仅证明无关恒真式、用不可能前提排除实际输入，或把所需结论直接当成前提；When 审查目标证明义务；Then 不承认已解决原正确性问题，要求修正契约或模型。不得通过删掉 UML 失败分支来使证明变得容易。

### S-36 验证失败或无法验证（R-25、R-28）

分别给出 Lean 工具链不可用、当前文件检查失败、存在 `sorry`/`admit`/未解目标，以及未证明自定义公理支撑结论的情形。Then 报告未完成/阻塞及真实诊断，不输出证明已通过；不能以自然语言回译、历史日志或一次成功运行代替实际文件的证明检查。

### S-37 可选性与跳过不赋予证明资格（R-17、R-28）

Given 项目未采用此 skill；Then 普通 OMD 跟踪不依赖 Lean。Given 某范围已采用、但必要 link 缺失或过期；When 显式跳过/关闭检查；Then 保留缺口与原标记状态，不声称程序性证明交付完成。

## 不伪装成已经有答案的边界测试

完成对应 Q 后再定唯一预期：

- 范围前/内/边界插入，范围删除/拆分，重复内容的候选映射（Q-01）。
- A↔B、A↔C 的独立确认，A→B→C 的传播与环（Q-02）。
- alias 指向变更、外部项目不可访问、当前/固定快照（Q-03）。
- import 后新增文件、移动/复制/重叠目录（Q-04）。
- command 重跑时机、副作用、输出模式、超时/截断（Q-05）。
- 检查集/阶段转移、重叠覆盖聚合、单写者崩溃恢复（Q-06/Q-08/Q-09）。

所有场景均为未来验收草案。本次文档链接/引用检查不等同于上述产品行为已经验证。
